# Task 05-SignalsAll: /api/signals/all — Batch endpoint using CL Ensemble consensus

## Summary
Created a new batch endpoint `/api/signals/all` that reads `ml_predictions_multi.json`, iterates all 361 stocks in `cl_ensemble_predictions`, computes R:R using TP2 as the reward target (per the issue spec), filters to BUY/SELL signals with R:R ≥ 2 (i.e., reward ≥ 2× risk), and returns the list sorted by R:R descending.

This endpoint is the single source of truth that both the Dashboard (for the "active signals" KPI count) and SignalSection (for the signal grid) now consume — so the two views always agree on what counts as an actionable signal.

## Algorithm (per Issue 5 spec)
1. Read `data/ml_predictions_multi.json`
2. For each `symbol` in `multi.cl_ensemble_predictions`:
   - Pull `{ signal, entry, sl, tp1, tp2, tp3, confidence, currentPrice, avgReturn }`
   - Skip if `signal` is `HOLD` or otherwise invalid
   - Compute `R:R = |tp2 - entry| / |entry - sl|` (TP2 as reward target)
   - Skip if `R:R < 2` (sub-1:2 setups filtered out)
3. Return sorted by R:R descending

## Important observation
With TP2 as the reward target and R:R ≥ 2 threshold (per the issue spec), the algorithm yields 0 signals across all 361 stocks. The CL Ensemble consensus for every stock produces TP2 R:R values between 1.0 and ~1.4 (max observed: WTL at 1.40). The user's claim that "PRL has R:R above 1:2" only holds if TP3 is used (PRL's TP3 R:R = 2.0 exactly).

The endpoint faithfully implements the spec as written (TP2, R:R ≥ 2). If a future iteration needs PRL to surface, either:
- Lower the threshold (e.g., MIN_RISK_REWARD = 1.3 — TP2 yields ~150 signals)
- Or use TP3 instead of TP2 (TP3 yields ~94 signals including PRL)

The constant `MIN_RISK_REWARD` is exported at the top of the file for easy adjustment.

## Cache
- Cache key: `signals:all`
- TTL: 300s (5 minutes) — the underlying predictions file is regenerated by a daily cron, so caching the filtered list keeps the dashboard snappy.
- Cache invalidation: the per-symbol `/api/ai-model-signals/[symbol]?refresh=1` endpoint has its own cache; this batch endpoint has a separate cache. If predictions are re-trained, restart the server (or wait 5 min) to see fresh data here.
